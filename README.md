# REEF אשקלון · מערכת מעקב אינסטלציה
### ש.ה.ב.ל תשתיות ומערכות מים בע״מ · 054-6947773

מערכת אינטרנטית למעקב אחרי עבודות האינסטלציה במלון ריף באשקלון: 3 בניינים, 10 מפלסים, 98 חדרים ומרתף.
האתר פותח בהדמיית תלת־ממד חיה של המלון, והתאורה בה מותאמת לשעה באשקלון. אחרי הפתיח מגיעים לדשבורד, משם בוחרים בניין, מפלס וחדר, ובכל חדר מעדכנים שלבי עבודה, בדיקות, פערים ואישור עם שם הבודק.

## שלב 1: העלאה ל-GitHub (אתר חי)
1. יוצרים מאגר (Repository) חדש ב-GitHub, למשל `shbl-reef`.
2. מעלים את כל הקבצים מהתיקייה, כולל כל התיקיות.
3. נכנסים ל-**Settings → Pages**, ובוחרים: Source = `Deploy from a branch`, Branch = `main`, Folder = `/ (root)`.
4. אחרי כדקה האתר זמין בכתובת `https://<שם-המשתמש>.github.io/shbl-reef/`

> עד שמחברים את הדרייב (שלב 2) האתר עובד ב**מצב הדגמה**: הנתונים נשמרים רק בדפדפן, ומוצגים נתוני דוגמה כדי שיהיה מה להראות.

## שלב 2: חיבור לגוגל דרייב (שמירה אוטומטית ומשותפת)
מבצעים את השלב הזה בחשבון הגוגל של החברה, זה שבדרייב שלו יישמרו הנתונים.

1. נכנסים ל-[script.google.com](https://script.google.com) ויוצרים **פרויקט חדש**. אפשר לקרוא לו `REEF - שרת`.
2. מוחקים את התוכן הקיים ומדביקים את כל התוכן של הקובץ `Code.gs` (נשלח בנפרד, לא נמצא במאגר).
3. שומרים, בוחרים את הפונקציה **`setup`** בתפריט העליון ולוחצים **Run**. מאשרים את ההרשאות לדרייב ולגיליונות.
   הפונקציה יוצרת בדרייב את התיקייה **"ש.ה.ב.ל - REEF מעקב אינסטלציה"**, ובתוכה קובץ נתונים, גיליון יומן וגיבוי יומי.
4. לוחצים **Deploy → New deployment**, ובוחרים סוג **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
5. מעתיקים את כתובת ה-Web app (מסתיימת ב-`/exec`) ומדביקים אותה בקובץ `js/config.js`:
   ```js
   API_URL: 'https://script.google.com/macros/s/XXXXXXXX/exec',
   ```
6. מעלים את `config.js` המעודכן ל-GitHub. מעכשיו כל עדכון, לא משנה מאיזה מכשיר, נשמר אוטומטית בדרייב.

> חשוב: אחרי כל שינוי בקוד השרת צריך לבחור **Deploy → Manage deployments → Edit → New version**, כדי שהכתובת תמשיך לעבוד עם הקוד החדש.

## קוד הגישה ואבטחה
- **קוד התחלתי:** הקוד שנמסר לכם בנפרד (מוגדר בקובץ השרת שנמצא רק ב-Google Apps Script).
- כולם יכולים **לצפות** בדשבורד. כדי **לעדכן** צריך ללחוץ על 🔒 ולהזין שם מלא וקוד. כל שינוי נרשם ביומן עם שם המעדכן.
- **הקוד לא נמצא בקוד האתר.** הוא נבדק רק בשרת של גוגל, ושם נשמר כגיבוב SHA-256 עם מלח אקראי. מי שפותח את קוד המקור של האתר לא ימצא אותו.
- אחרי 6 ניסיונות שגויים המערכת ננעלת ל-15 דקות, וכל ניסיון כושל נרשם בגיליון היומן.
- **החלפת קוד:** בעמוד **הגדרות → החלפת קוד גישה**, במצב עריכה. מומלץ להחליף את הקוד ההתחלתי מיד אחרי ההתקנה.
- אם שכחתם את הקוד: בעורך הסקריפט מריצים את `emergencyResetCode`, והקוד חוזר לקוד ההתחלתי.
- האתר חסום להטמעה בקוד זדוני (CSP), כל טקסט שמוזן מנוטרל, והשרת מוודא שכל קלט תקין לפני שהוא שומר אותו.

## מבנה הפרויקט (ברירת מחדל)
המבנה נבנה לפי תוכנית הקומה ששלחתם: **12 חדרים בכל קומה, 4 בכל בניין**:
- בניין A, הכנף העליונה: חדרים 01–04
- בניין B, הכנף האמצעית: חדרים 05–08
- בניין C, הכנף התחתונה: חדרים 09–12

מספר חדר = קומה + מספר, למשל **305** הוא קומה 3, חדר 05, בבניין B.
כדי להגיע ל-98 חדרים, קומות 1–8 מלאות (96 חדרים) ובקומה 9 פעילים רק 905 ו-906. **אפשר לשנות את זה** בעמוד **הגדרות → מבנה הפרויקט**: במצב עריכה לוחצים על חדר כדי להפעיל או לכבות אותו.
המרתף, קומת הקרקע והגג מופיעים כ"מערכות ושטחים": חדר משאבות, מאגרים, מטבח, בריכה וכו'.

## מה מעדכנים בכל חדר
1. **שלבי עבודה:** שרוולים, ניקוז, צנרת מים, אישור סגירה, כלים סניטריים
2. **בדיקות מערכת:** בדיקת לחץ (בבר), בדיקת אטימות ניקוז, בדיקת תפקוד סופית. כל בדיקה נרשמת כ"עבר" או "נכשל" עם שם הבודק
3. **פערים:** טקסט חופשי, ואחר כך סימון "טופל" עם שם מי שטיפל
4. **אישור מסירה:** אישור סופי עם שם המאשר

סטטוס החדר מחושב אוטומטית: טרם החל / בעבודה / פער פתוח / הושלם וממתין לאישור / נבדק ואושר.
בעמוד היומן יש כפתור **ייצוא CSV** שיוצר דוח מלא שנפתח באקסל.
